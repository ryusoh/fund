## 4. F1 — Remove `?t=<timestamp>` cache-busting everywhere except the Cloudflare Worker call

**Effect/effort.** Repeat visits re-download ~10 MB of static JSON/CSV per
page load today; after this change unchanged files revalidate (304) instead of
re-downloading (200). Effort: ~30 changed lines plus tests.

**Service worker finding (already investigated — do NOT re-check, do NOT touch
`sw.js`).** `sw.js` exists at the repo root and handles `/data/` URLs with a
**network-first** strategy (`sw.js:146-150`, `networkFirst` at `sw.js:110-112`):
it always goes to the network and only falls back to cache offline. Therefore
removing the query param does NOT change freshness semantics under the service
worker — data URLs are never served cache-first. The cache-bust today only
defeats the browser HTTP cache underneath the SW's own `fetch(req)`, forcing a
full 200 where a 304 revalidation would do. It also pollutes the SW cache with
dead uniquely-keyed entries; those age out whenever `CACHE_NAME` next bumps and
need no action. `sw.js` and `js/ui/service_worker_register.js` are off-limits.

**Scope.** You MAY edit only: `js/services/dataService.js`,
`js/transactions/realtimeData.js`,
`js/transactions/terminal/stats/financial.js`,
`tests/js/services/dataService.test.js`,
`tests/js/transactions/realtimeData.test.js`,
`tests/js/transactions/terminal/stats/financial.test.js`.
All other files are off-limits.

**Context.** `fetchJSON` in `dataService.js` appends `?t=<Date.now()>` to every
request; the same pattern exists in `realtimeData.js` and as `withCacheBust()`
in `financial.js`, plus the historical CSV / FX fetch in `dataService.js`'s
`fetchData`. Replace with `fetch(url, { cache: 'no-cache' })`, which forces
ETag/`Last-Modified` revalidation without changing the URL. Keep a manual
bypass ONLY for the Cloudflare Worker live-prices call, which is genuinely
volatile (and cross-origin, so the SW never sees it). See
`docs/performance.md` section F1.
